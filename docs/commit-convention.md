# 커밋 컨벤션

## 타입

| 타입 | 설명 |
| --- | --- |
| `feat` | 새로운 기능 추가 |
| `fix` | 버그 수정 |
| `refactor` | 코드 리팩토링. 기능/동작에 영향이 없는 서식·포맷 변경도 포함 |
| `docs` | 문서 추가/수정 |
| `test` | 테스트 코드 추가/수정 |
| `chore` | 빌드 설정, 패키지 매니저, 기타 잡무 |
| `note` | 위 항목에 속하지 않는 기록성 변경 (주석, 메모 등 코드 동작에 영향 없는 변경) |

- `style` 타입은 별도로 사용하지 않습니다. 코드 의미에 영향이 없는 서식 변경(들여쓰기, 세미콜론, 줄바꿈 등)은 `refactor`로 처리합니다.

## 작성 규칙

- 형식: `type: subject`
- subject는 한국어로 작성합니다.
- 제목(subject)은 짧고 명확하게 작성합니다.
- 제목 끝에 마침표(`.`)를 붙이지 않습니다.
- 서로 관련 없는 변경 사항은 하나의 커밋에 묶지 않고 각각 별도의 커밋으로 분리합니다.

예시:
```
feat: 레시피 검색 기능 추가
fix: 로그인 리다이렉트 오류 수정
refactor: 들여쓰기 및 코드 포맷 정리
docs: 브랜치 컨벤션 문서 추가
test: 레시피 검색 유닛 테스트 추가
chore: eslint 설정 업데이트
note: 임시 확인용 주석 추가
```

## 자동 검증

`commitlint` + `husky`로 커밋 시점에 위 타입/형식을 자동 검증합니다. 규칙은 [commitlint.config.mjs](../commitlint.config.mjs)에 정의되어 있습니다.
