# 02. 분석 API 설계

- 작성자: 김도혁
- 날짜: 2026-10-02

## 1. 개요

유튜브 주소나 직접 입력한 레시피를 받아 재료·가격·사 먹는 가격을 계산하는 `POST /api/analyze`를 recipe-web에 이식한다.
기존 서비스(synergy-mvp)에서 검증된 분석 파이프라인을 **그대로** 옮기고, 결과를 화면 계약(`AnalyzeResponse`)으로 바꾸는 어댑터와 라우트를 만든다.

- 선행 문서: [01 서버 기반](./01-server-foundation.md), [06 결과 화면](./06-result-screen.md)(응답 스키마와 금액 계산식을 먼저 구현)
- 후속 문서: [04 있는 재료로 찾기 API](./04-pantry-api.md)(가격 파이프라인 공유)

## 2. 목표 / 비목표

### 목표

- MVP 분석 파이프라인(`lib/recipe/**`, JS 26개 파일)을 `apps/web/src/server/recipe/`로 옮긴다.
- 파이프라인 출력을 화면 계약으로 바꾸는 어댑터와 `POST /api/analyze` 라우트를 구현한다.
- 요청 대기 시간(60초)과 입력 길이 제한을 정하고, 서버가 보내는 오류 안내 문구가 화면에 닿게 한다.

### 비목표

- 파이프라인 알고리즘 개선(재료 파싱, 가격 매칭, 프롬프트). **수정 금지**다.
- 조리 단계(`steps`) 추출. 파이프라인이 추출하지 않으므로 빈 배열이다.
- 분석 결과 캐싱이나 저장.
- 외부 서비스 연동 검증(YouTube·Gemini·KAMIS 키, Supabase DB). 키와 DB가 준비된 뒤 직접 확인한다.

## 3. 배경 / 현재 상태

- 화면(홈)은 이미 `analyzeRecipe()`로 `/api/analyze`를 부른다. 서버가 없어서 동작하지 않았다.
- 응답 스키마 전체와 금액 계산식(`calc.ts`)은 결과 페이지 작업(#17)에서 먼저 구현했다. 이 작업은 그 두 커밋을 가져와서 시작했다.
- MVP 원본: `src/lib/recipe/**`, `src/lib/recipe-adapter.ts`, `src/lib/data/store-price.ts`, `src/app/api/analyze/route.ts`, `src/instrumentation.ts`
- MVP 검증 결과: 재료 추출 성공률 60%, 홀드아웃 재현율 95% / 정밀도 91%. 설명란과 고정 댓글 모두에서 재료를 못 찾는 비율이 약 35%로, 오류가 아니라 정상 경로다.

MVP와 달라지는 점:

- `env.js`(`.env` 파일 직접 읽기)를 대체본으로 바꿨다. Next.js가 환경변수를 주입하므로 파일을 읽지 않는다.
- 목 응답 분기(`USE_MOCK`, `?mock=`)와 `lib/mock`은 옮기지 않았다.
- `lib/data/unmatched.ts`는 옮기지 않았다. MVP에서 어디서도 부르지 않는 코드였다.
- 라우트가 입력을 더 엄격히 검증한다(유튜브 주소 형식 공통 함수, 텍스트 20,000자 제한).
- 계약이 `types/api.ts`(TS 타입)에서 `@recipe-web/api`의 Zod 스키마로 바뀌었다.

## 4. 요구사항

### 요청

```ts
{ url: string } | { text: string }
```

- 주소와 텍스트가 모두 오면 주소로 분석한다. 앞뒤 공백은 지운다.
- 주소는 유튜브 형식만 허용한다. 직접 입력은 20,000자까지다.

### 응답 (`status`로 분기)

| status | 의미 | HTTP | 화면 처리 |
| --- | --- | --- | --- |
| `success` | 계산 완료 | 200 | 결과 화면 |
| `no_recipe_found` | 재료를 찾지 못함, 영상을 가져오지 못함(비공개·삭제·차단 포함) | 200 | 홈 추출 실패 카드(직접 입력 안내) |
| `error` / `INVALID_URL` | 주소·입력이 비었거나 유튜브 주소가 아님 | 400 | 홈 계산 실패 카드 |
| `error` / `INVALID_INPUT` | 본문을 읽지 못함, 텍스트가 너무 김 | 400 | 홈 계산 실패 카드 |
| `error` / `INTERNAL` | 예상하지 못한 오류 | 500 | 홈 계산 실패 카드 |

- 영상을 가져오지 못한 경우(비공개·삭제·차단)는 오류 코드가 아니라 `no_recipe_found`의 `message`로 이유를 알린다. 사용자가 레시피를 직접 붙여 넣어 계속할 수 있기 때문이다. 이전 설계의 `FETCH_FAILED`·`RATE_LIMITED` 코드는 만들어지지 않는다.
- 응답 문구는 한국어이고 사과 표현 없이 다음 행동을 알려 준다(MVP 지시서 1-7). 내부 오류 내용은 응답에 담지 않고 서버 로그에만 남긴다.

### 금액 규칙

- 원 단위 정수로 표기하고 날짜는 `YYYY-MM-DD`다.
- 서버는 초기 1회만 계산한다. 이후 재료 조정은 화면이 `calc.ts`로 다시 계산한다.

## 5. 상세 설계

### 5.1 파일 배치

```
apps/web/src/server/recipe/**            # 파이프라인 26개 파일 (JS + .d.ts, 25개는 MVP 원본 그대로)
apps/web/src/server/adapters/analyze.ts  # 파이프라인 출력 → AnalyzeResponse
apps/web/src/server/data/store-price.ts  # 사 먹는 가격 DB 조회 (match_store_price)
apps/web/src/app/api/analyze/route.ts    # 입력 검증 + 파이프라인 + 어댑터
apps/web/src/instrumentation.ts          # 외부 호출이 IPv4를 먼저 쓰도록 설정
packages/api/src/client/analyze-recipe.ts   # 대기 시간 60초, 400·500 응답을 값으로 읽기
packages/api/src/schemas/analyze.ts         # ANALYZE_TEXT_MAX_LENGTH
apps/web/eslint.config.mjs                  # server/recipe/** 검사 제외
```

### 5.2 파이프라인

```
fetch(설명란 → 고정 댓글 → 블로그 링크) → parse(재료 규칙 5종, 단위 환산, 인분)
  → normalize(규칙 → DB 별칭 캐시 → Gemini) → price(KAMIS 실시세 → 시드)
```

- **원본 그대로 옮겼다.** MVP 파일과 저장소 파일의 해시를 비교해 26개 중 25개가 같다. 다른 하나(`env.js`)는 의도적인 대체본이다.
- 원본 파일의 주석은 지우지 않았다. 주석에 "왜 그렇게 했는지"가 들어 있어서(MVP 지시서 1-9) 지우면 같은 버그를 다시 만들 수 있다.
- 키가 없으면 해당 단계를 건너뛴다. 코드가 이미 처리한다.

| 없는 것 | 동작 |
| --- | --- |
| `GEMINI_API_KEY` | AI 정규화·매장가 추정 건너뜀. 규칙으로 풀리는 이름만 사용 |
| `KAMIS_CERT_KEY`·`KAMIS_CERT_ID` (둘 다 필요) | 시드 가격으로 계산(모든 가격이 `estimate`) |
| `YOUTUBE_API_KEY` | API 대신 페이지 분석 경로 사용 |
| `SUPABASE_SECRET_KEY` | 별칭 캐시가 메모리 모드, 사 먹는 가격은 없음 |

- 파이프라인이 읽는 선택적 환경변수: `GEMINI_API_KEYS`(키 목록), `GOOGLE_API_KEY`, `GEMINI_MODEL`, `LLM_PRICE`(`0`이면 웹 가격 조회 끔), `NAVER_CLIENT_ID`·`NAVER_CLIENT_SECRET`, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`. `.env.example`에는 필수 키만 적는다.

### 5.3 어댑터 (`toAnalyzeResponse`)

- 재료가 없거나 가져오기에 실패하면 `no_recipe_found`(영상 제목, 썸네일, 이유 문구)를 돌려준다.
- 성공이면 재료 한 줄을 `IngredientRow`로 바꾼다. 번호는 1부터, 가격 출처에 따라 `actual`(KAMIS 실시세) / `estimate`(시드) / `user`로 구분한다.
- 조미료 분류, 조리 단계 문장 조각(`…하기`, `…준비`, 인분 표기)은 `seasoning`으로 내려 "가격 없는 주재료" 경고에서 뺀다.
- 사 먹는 가격은 Gemini 추정(중앙값)을 먼저 쓰고, 없으면 DB(`match_store_price`)로 찾는다. 둘 다 없으면 `store: null`이다.
- 합계·경고는 `lib/calc.ts`로 계산한다(서버와 화면이 같은 계산식).
- 가격 기준일은 재료 가격 중 가장 최근 날짜, 없으면 파이프라인의 기준 날짜다.

### 5.4 라우트

- `runtime = "nodejs"`: 파이프라인이 `node:https`를 쓴다(Edge 런타임에는 없다).
- `maxDuration = 60`: 유튜브와 AI 호출이 겹치면 10초를 넘는다.
- 처리 순서: 본문 파싱 → 주소·텍스트 검증 → 파이프라인 → 어댑터 → JSON 응답.
- 파이프라인이 입력 오류(`statusCode: 400`)를 던지면 그 문구와 함께 400, 그 밖의 예외는 고정 문구와 함께 500이다.

### 5.5 클라이언트 호출 (`analyzeRecipe`)

- 요청별 `timeout: 60_000`. 공통 기본값(10초)보다 길다. 자동 재시도는 없다(비용이 큰 호출이 두 번 나가지 않도록).
- 400·500 응답도 본문이 `error` 형식이면 오류로 던지지 않고 값으로 돌려준다. 서버의 구체적인 안내 문구("레시피는 20,000자까지 넣을 수 있어요")가 홈 계산 실패 카드에 그대로 나오게 하기 위해서다. 본문이 형식에 맞지 않거나 다른 HTTP 오류(503 등)이면 오류로 던진다.

## 6. 결정사항

| 결정 | 고려한 대안 | 선택 이유 |
| --- | --- | --- |
| 파이프라인은 JS 그대로 이식하고 lint 대상에서 제외한다 | TS로 변환하거나 리팩터링 | 실데이터 60건으로 검증된 로직이다(MVP 지시서 1-1). 변환 중 동작이 바뀌면 다시 검증할 방법이 없다. 별칭 매칭에 앵커(`^`)를 쓰지 않는 규칙(1-2)도 그대로다. |
| 원본 파일의 주석을 지우지 않는다 | 이 저장소의 "주석 없음" 규칙 적용 | 주석에 판단 근거가 들어 있다(1-9). 이 규칙은 새로 작성하는 코드(어댑터, 라우트 등)에만 적용한다. |
| `env.js`만 대체본으로 바꾼다 | 각 파일의 `import "../env.js"` 줄 삭제 | 원본 파일을 건드리지 않는 가장 작은 변경이다. 대체본은 파일을 읽지 않고, 키 값은 드러내지 않는다(원본은 길이와 끝 4글자를 보여줬다). |
| 영상을 가져오지 못한 경우도 `no_recipe_found`로 돌려준다 | 별도 오류 코드(`FETCH_FAILED`) | MVP에서 검증된 동작이다. 사용자가 직접 입력으로 이어갈 수 있다. |
| 텍스트를 20,000자로 제한한다 | 제한 없음 | 긴 텍스트가 AI 호출 비용으로 이어진다. 북마크 원문 상한([03 문서](./03-bookmark-api.md))과 같아서, 저장한 직접 입력은 항상 다시 분석할 수 있다. |
| 요청 대기 60초, 자동 재시도 없음 | 기본 10초, 1회 재시도 | 실제 처리 시간이 10초를 넘는다. 재시도하면 비용이 큰 AI·유튜브 호출이 두 배가 된다. |
| 400·500 응답을 값으로 읽는다 | 모두 오류로 던지기 | 서버의 한국어 안내 문구가 화면에 닿는다. 오류로 던지면 일반 문구로 바뀐다. |
| `unmatched.ts`는 옮기지 않는다 | 함께 이식 | 어디서도 부르지 않는 코드다. 필요해지면 그때 추가한다. |
| 별칭 캐시(`alias-store.js`)는 원본의 자체 Supabase 접속을 그대로 쓴다 | 관리자 클라이언트로 교체 | 원본 파일을 수정하지 않는 것이 우선이다. 환경변수 이름(`SUPABASE_SECRET_KEY`, `NEXT_PUBLIC_SUPABASE_URL`)이 같아서 동작한다. 정리는 후속으로 미룬다. |
| 사 먹는 가격 DB 조회가 실패해도 분석을 막지 않는다 | 오류로 응답 | 사 먹는 가격은 비교용 부가 정보다. 없으면 화면이 비교 영역을 접는다. |

## 7. 예외·오류 처리

| 상황 | 응답 |
| --- | --- |
| 본문이 JSON이 아님·객체가 아님 | 400 `INVALID_INPUT` |
| 주소·텍스트 모두 없음 | 400 `INVALID_URL` |
| 유튜브 주소 형식 아님 | 400 `INVALID_URL` |
| 텍스트 20,000자 초과 | 400 `INVALID_INPUT` |
| 영상 비공개·삭제·차단, 재료 0개 | 200 `no_recipe_found` |
| 예상하지 못한 예외 | 500 `INTERNAL`(고정 문구) |

- 외부 서비스 키·DB 오류는 로그에만 남고 사용자 응답에는 담기지 않는다.
- 클라이언트 응답 검증에 실패하면 `validation` 오류로 처리하고 홈 계산 실패 카드를 보여준다.

## 9. 테스트 / 완료 기준

확인한 것:

- **파이프라인(외부 연결 없이, 네트워크 차단):** 직접 입력 레시피를 끝까지 계산(재료 6개, 소모 원가 8,410원, 구매 단위 29,300원), 재료 이름·환산 근거(두부 1/2모 → 150g 등), 시드 가격 표시, 가격 없는 재료는 `null`, 별칭 규칙(통삼겹 → 돼지고기), 입력이 없으면 400 오류, 대체본 `env.js`가 파일을 읽지 않고 키 값을 숨김
- **어댑터:** 유튜브/직접 입력 변환, 재료 한 줄 변환, 합계·경고가 `calc`와 일치, 가격 출처 구분, 가격 기준일, 사 먹는 가격 우선순위(추정 → DB → 없음), 조리 단계 문장 조각 분류, 재료를 찾지 못한 경우, 썸네일 주소 5가지 형태, 응답이 화면 스키마와 일치
- **사 먹는 가격 조회:** 변환, 최소·최대 대체, 결과 없음, DB 오류·클라이언트 생성 실패 시 null
- **라우트:** 입력 검증 12종, 공백 제거, 주소 우선, 200 / 400 / 500 응답, 내부 정보 비노출, 사과 표현 없음, 실행 설정
- **전체 흐름(파이프라인 + 어댑터 + 라우트, 네트워크 차단):** 응답이 화면 스키마와 일치, 절약 금액 계산, 경고, 재료를 찾지 못한 문장
- **클라이언트:** 대기 시간 60초, 400·500 응답 읽기, 형식 없는 500과 503은 오류로 던짐
- **파일 무결성:** 이식한 파이프라인 26개 중 25개가 MVP 원본과 해시까지 같다.
- **실제 서버(`next start`, 프로덕션 빌드):** 직접 입력 레시피가 200으로 응답(첫 요청 0.07초, 이후 0.006 ~ 0.01초), 입력 오류가 모두 400, 키·DB가 없어도 요청이 실패하지 않음(안전하게 대체)
- 린트, 타입 검사, 빌드 통과

직접 확인이 필요한 것(키와 DB가 필요하다):

- 실제 유튜브 링크 3종(성공, 재료 없음, 비공개)과 직접 입력으로 전체 흐름 확인
- `GEMINI_API_KEY`, `YOUTUBE_API_KEY`, `KAMIS_CERT_KEY`·`KAMIS_CERT_ID`를 넣었을 때의 동작(AI 정규화, 실시세)
- DB 함수 `match_store_price`, `lookup_alias`, `cache_alias`, `record_unmatched`의 동작(마이그레이션 적용 후)

## 10. 미결 사항

- `PRICE_GO_SERVICE_KEY`는 파이프라인 어디에서도 읽지 않는다. 쓰이지 않는 설정이면 [01 문서](./01-server-foundation.md)의 환경변수 목록에서 뺀다.
- `normalize` 통계(규칙/캐시/AI/실패 개수)를 화면에 노출할지 정하지 않았다. 현재는 받기만 한다.
- `steps`가 항상 빈 배열이므로, 06 문서의 조리법 탭은 원문(`rawText`) 중심으로 구성한다. 직접 입력은 `rawText`도 `null`로 내려온다.
- 직접 입력의 `videoTitle`이 "직접 입력"으로 내려오고 기본 안내가 "영상에서…"로 시작한다(MVP 동작). 홈 화면은 자체 문구를 쓰므로 영향이 없다.
- 별칭 캐시의 자체 Supabase 접속을 관리자 클라이언트로 합칠지.
